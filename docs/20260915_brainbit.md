# BrainBit acquisition and recording fixes — 2026-09-15

## Evidence from the reported recording

The supplied external installation and its recording were inspected read-only.
No participant data, machine settings, or files in that installation were changed.
This report omits participant and device identifiers.

The session started its recording preflight at 10:15:44 UTC. About 5.6 seconds
later the central readiness check rejected study onset because EEG was missing.
The checkpoint files consistently reported zero EEG, quality, band and mental
samples, and one battery sample. Reading the XDF independently with `pyxdf`, with
clock correction and dejittering disabled, confirmed that it contains just one
battery stream and one sample. It does not contain a usable EEG recording.

The worker remained alive for about 15 minutes before its web-server lease
expired. The late worker cleanup is separate from the earlier failed preflight;
the central study-start check did detect the missing EEG.

The plugin log shows a connection at 10:14:48 UTC and calibration finishing at
10:15:17. At 10:15:43, immediately before preflight, it reports creation of the
base LSL outlet again. The SDK identified the device as `LEBrainBit2`, with
channels `O2, T3, T4, O1`. This evidence must not be treated as a hardware test of
the classic BrainBit. Runtime channel mapping remains authoritative.

Two code defects explain important parts of the failure:

1. Study preflight calls plugin initialization again. The adapter recreated its
   LSL outlets, leaving only its base outlet, while its already running CLI was
   retained. That CLI had already emitted its channel map, so the EEG outlet was
   not recreated. Initialization now reuses unchanged live acquisition, including
   when the just-connected device becomes the remembered target. Real changes
   stop the old acquisition before rebuilding outlets.
2. The log contains a protocol response joined to a plugin print on the same
   line. A JSON parser cannot accept that frame. Plugin diagnostic output now
   uses stderr; protocol stdout is written in one locked operation. CLI output
   from its own callback threads is also serialized. Control operations include
   request identifiers in diagnostics so future restarts can be attributed.

These are code and log findings. A successful real-headset recording after the
fix still needs to be performed.

## Corrections to the earlier notes

The original reports are preserved in
[the report archive](archive/brainbit-20260915-reports.md).

- Decimal exit code `3221225786` is `0xC000013A`, Windows
  `STATUS_CONTROL_C_EXIT`. An access violation is `0xC0000005`
  (`3221225477`, or signed `-1073741819`). These now have separate explanations.
  The original code alone does not identify who sent the console interruption.
  See [Microsoft's status-code reference](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-erref/596a1078-e883-4972-9bbc-49e60bebca55).
- Outlet recreation is not limited to a Restart action. Repeated Initialize
  during normal study startup was sufficient.
- The supplied XDF supports the conclusion "EEG was not recorded". It does not
  support a claim that a complete EEG session was recorded and later corrupted.

## Implemented behavior

### Connection and operator controls

- Connection state, EEG reception, calibration and warnings are separate facts.
  Each connection gets an identifier; old measurements and graph history are
  cleared on disconnect and reconnect. On-disk status from a previous process
  is history, not current sensor data.
- Current messages follow current state. Old error translation keys and retry
  details are cleared on recovery. The last connection event retains its time.
- Battery warning begins at 20 percent or below and clears at 25 percent.
  Invalid or more than 120-second-old readings are marked unknown or outdated.
- Device selection uses a keyboard-accessible dropdown and one Connect action.
  Polling retains the native dropdown, its focus and selected identity.
- Serial number has priority over address. Names and scan indexes never decide
  automatic connections. A missing saved target does not select another band.
  With no target, a full scan auto-connects only one identifiable device;
  several devices require a choice. An explicit new scan always waits for a choice.
- The last successful identity is saved separately from the explicit target.
  Persistence merges changed settings into the current machine configuration.
- Search again and Check electrode contact are explicit, confirmed actions.
  They respect the existing central runtime lock. Study-start rules are unchanged.
- SDK disconnect/out-of-range events trigger recovery. An unexpected clean CLI
  exit in continuous mode is retried; a deliberate stop or timed acquisition
  still ends normally.

### Dashboard and scientific data

- The plugin renders two SVG histories: relative band-power shares and the SDK's
  instant/relative attention and relaxation indices. Each holds at most 60
  points per series at no more than 1 Hz. Recording rates are unchanged.
  Invalid windows, stalls and connection boundaries break graph lines.
- Raw values, channel order, resistance in ohms, contact measurement time,
  packet information and stream availability remain in technical details.
  The contact ratio is a diagnostic conversion, not a validated quality percent.
  Live artifact flags are independent of the earlier contact measurement.
- Raw EEG is decoded in the declared channel order and converted from volts to
  microvolts without additional filtering, rounding or interpolation.
  Failures of the optional emotional-math library do not stop valid raw EEG.
- Derived processing drains the SDK after each input frame. Artifact flags,
  calibration and ambiguous SDK output batches are propagated as validity
  metadata; uncertain data does not enter a valid preview or a valid sidecar
  average. The numeric LSL streams retain their existing channel contracts.
- `BrainBit_DIAGNOSTICS` adds JSON events for connection, device/SDK metadata,
  contact, calibration, artifacts, timing, packet issues, dropped samples and
  derived validity. Transitions are not reduced to the 1 Hz status history.
  Periodic snapshots include facts from before recording began. Acquisition-end
  diagnostics retain the final facts before connection state is cleared.
- Each CLI acquisition anchors epoch time to a monotonic clock. The adapter
  holds a stable conversion to LSL time and records its offset in clock/timing
  diagnostics. Arrival times and reconstructed sample times remain separate.
  Known counter gaps remain gaps; resets, duplicates and unknown counters are
  explicit. Missing samples are not synthesized.
- Gaps, decode errors and queue overflow reset derived calculation windows and
  calibration. No derived window silently spans such a discontinuity.

The SDK can repeat earlier derived values during bilateral artifacts; retaining
validity alongside the numeric streams is therefore necessary. Attention and
relaxation are algorithmic indices, not independently validated measurements of
a participant's mental state. See the
[manufacturer's algorithm contract](https://sdk.brainbit.com/lib-emotions/).

## Verification

Automated verification results are recorded below after the final suite run.
Fixtures use isolated temporary paths and simulated SDK data, never study data.

- Lifecycle, stale-state clearing, battery hysteresis, safe selection, persistence
  and repeated initialization have regression tests.
- Raw data survives optional math initialization and processing failures.
  Synthetic packet gaps reset the derived calculation without discarding raw frames.
- A native XDF round trip verifies four known EEG frames, microvolt values,
  channel order, 4 ms sample spacing and recorded calibration/artifact diagnostics.
  This tests the adapter publication interface and the native file writer;
  it does not measure BLE or live LSL transport performance.
- A headless Edge fixture uses the real plugin and central renderer at desktop
  and tablet widths, tests ten polling updates while the dropdown is focused,
  and verifies one action per confirmation, graph rendering and current messages.

### Hardware acceptance still open

1. Repeat installation/start and an actual recording on Windows and available
   macOS Intel and Apple Silicon machines.
2. Use two headsets to test explicit selection, missing target and reconnect.
3. Record contact loss, blinking, movement, Bluetooth interruption and recovery.
4. Record at least 60 minutes and inspect raw sample counts, timing drift, queue
   losses, gaps and diagnostic completeness. Check CPU cost of per-frame derived
   processing on each supported machine.
5. Measure a common independent timing reference against study events and report
   offset and variability. LSL clock synchronization alone does not establish
   end-to-end latency or ERP/millisecond accuracy; see the
   [LSL time model](https://labstreaminglayer.readthedocs.io/info/time_synchronization.html).

No measured signal-quality score, timing accuracy or completed hardware acceptance
is claimed for the laboratory setup. The supplied failed session cannot establish
those properties.
