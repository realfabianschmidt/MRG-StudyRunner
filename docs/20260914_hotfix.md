# 20260914 hotfix: README cleanup and implementation plan

Date: 2026-09-14.

This document collects the code findings and proposed changes removed from the
folder READMEs. The current delivery is this plan, its documentation-index link,
and descriptive READMEs. **All code work packages below are open.** The application
still uses `extensions/`, the shared `main.css`, and the existing compatibility
routes. Update those descriptions only when the corresponding code changes land.

## Decisions and checked starting point

The owner selected the complete scope: small fixes, removal of all ten old HTTP
routes, the Plugin naming convention, card-owned styles, and separate migration
modules for studies, machine settings, and uploads.

- Keep `plugin_framework`, `Plugin`, `PluginContext`, `plugin_key`, and
  `/api/plugins`. Rename the categorized `extensions/` directory and its SDK to
  use Plugin names. Keep `ui.extensions`, which describes browser module hooks.
- Remove the old manifest `entry_point` field from validation and normalized
  output. An input manifest may still contain it as an ignored extra field.
  `runtime.entrypoint` remains the execution path. Keep API version 5.
- Preserve supported old study files, machine settings, and upload queues through
  migrations. Removing old HTTP routes does not remove old-data compatibility.
- Preserve existing worktree edits and untracked READMEs. Do not use real study
  data or hardware for verification. Do not rewrite historical archives or
  delete local cache directories as part of this work.
- Keep the root `app_server.py`, `self_check.py`, and `version.py` files in place;
  their roles and import paths do not require a structural change.

### E. Add card-owned CSS and split page styles

**Status: open. Dependencies: A, B's manifest cleanup, and D.**

Affected components: manifest asset validation, discovery and asset serving,
browser catalog/card loaders, page stylesheet links, card manifests, and the SDK
card template. There is no build step or additional asset registry.

- Permit `.js` and `.css` in `ui.assets`; continue to accept only JavaScript in
  `ui.extensions.*`. Preserve relative-path validation, declared-file checks,
  duplicate rejection, and containment inside the trusted plugin directory.
- Serve CSS as `text/css` through the existing asset route. Preserve
  `X-Content-Type-Options: nosniff` and the current cache policy.
- Add a generic stylesheet loader using `<link>`. Load a card's declared CSS
  assets, share concurrent requests, and maintain deterministic insertion order
  using catalog order and manifest asset order. Track catalog generation so stale
  loads cannot register a card or leave duplicate active stylesheet links.
- Register a card only after its module, Python defaults, and declared styles
  have loaded. CSS errors and a six-second timeout use the existing required-card
  failure path. Failed loads must be retryable. Cards without CSS still load.
- Move only card-owned rules into a `card.css` next to that card's `card.js` and
  declare it in the manifest. Do not create empty stylesheets for cards that use
  only shared controls. Include a working CSS example in the SDK card template.
- Keep fonts, design tokens, resets, shared buttons/fields, and the shared card
  frame in `main.css`. Add `study.css` for participant views and `admin.css` for
  the admin interface, including `.view-sweep`. Keep `ambient-bubbles.css` on the
  participant page. Load shared CSS before page CSS and plugin styles.
- Keep `.q-card-study`, `.card-instruction`, `.q-type-tag`, shared input/switch
  controls, and the reused `.stimulus-toggle-*` widget centrally available. The
  widget is also used for study-settings sensor/destination pickers. Separate
  page-specific variants from those shared rules using actual consumers.
- Preserve selector behavior, responsive layout, reduced-motion rules, branding,
  and overlays rendered outside the card container. Do not split by the old
  README line ranges: they contain mixed responsibilities and shared selectors.

Acceptance: manifests reject unsafe/nondeclared assets and CSS module entry
points; responses have correct MIME types; loader tests cover concurrency,
failure, timeout, retry, and generation changes. Every card renders and works in
the editor and participant page, including overlays and tablet layouts. Source
and packaged self-checks find the declared CSS. Existing cards with no own styles
continue to work.
