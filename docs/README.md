# Documentation Index

Active documentation lives directly in `docs/`. Historical plans and audits live
in `docs/archive/`; keep them for context, but do not treat them as current
implementation instructions unless an active document explicitly points there.

Recommended starting points:

- `../README.md`: GitHub landing page, run commands, packaging and release basics.
- `start-here.de.md`: German non-coder setup, HTTPS/iPad, sensors and updates.
- `operator-guide.md`: daily lab operation and project overview.
- `sensors-and-data.md`: sensor sources, runtime integrations, timing, XDF/LSL and result files.
- `developer-guide.md`: code structure, naming rules and integration plugin pattern.
- `release-and-update.md`: PyInstaller server ZIPs, updater keys, release flow and shortcuts.
- `../CONTRIBUTING.md`: project rules for clear, maintainable changes.

Naming rules:

- Python files use `snake_case.py`.
- Browser and doc asset files use `kebab-case`.
- Docs use descriptive names, not numbered prefixes.
- `Software/` is the repository root in the lab workspace.
- `software/` is the Python app folder and stays lowercase because imports,
  CI, release tooling and PyInstaller rely on it.

When the repo is used inside the lab workspace, `../../Sensorik/` is the
separate hardware and sensor reference folder. It is not generated by the app.
Runtime-ready sensor files that the app needs are copied into
`../software/study_runner/integrations/` and released from there.
